# 研究结论状态与填写规则

本任务当前只完成实现与CPU验证，**没有正式GPU推理结果**。
不据此声称TS-FSAR存在时间采样鲁棒性问题，也不支持立即开发/训练速度归一化模块。

正式运行的 `analyze` 会从真实 `.npz` 自动导出配对分数、CI、案例和报告。请逐项填写：

1. **身份/复现**：运行Git commit、checkpoint SHA256、1/5-shot各Episode数；
   E0历史像素和预测是否全部一致；是否有 failed/partial_timeout；绝不能用不完整
   E0的干预结果做机制解释。历史60.774%不是这200episode的期望固定准确率。
2. **A：序列级表示变化**：分别看CLIP/LSN逐索引、时间插值和同源帧余弦距离；
   报告公共时间覆盖、重复帧及其有效位置，不能把插值近似当作语义不变证明。
3. **B：分类变化**：四分支准确率、配对变化CI、纠正/破坏、预测改变和margin；
   gamma=.75/.5和1.33/2两条方向各自看剂量关系，不能只挑显著的gamma/shot。
4. **C：定位能力**：LSN含时间上下文，alpha-D含非线性，R/W又依赖采样位置。
   R/W代数分解能提示哪里数值变动，但不能在表示已经改变时宣称匹配机制额外失效。
   同源帧、时间匹配表示保持、正确类R证据、原始固定rival分解、两端同时扰动
   等证据需一致，才讨论H1b线索；没有这些对照只能定位到联合推理路径。
5. **E3对照**：比较同episode E1与对应随机对照的margin差CI，以及偏移RMS/重复率。
   对照实际扰动不完全匹配时必须保留该限制，不能将其差异自动归因于速度。
6. **融合归因**：记录 matching对/fusion错、matching错/fusion对、都对、都错的
   4×4转移；TS-DCM正确但融合变错，不能直接指向alpha-D缺陷。
7. **五个最终问题**：分别回答是否敏感、是否随强度增加、是否可定位表示/匹配、
   是否超过随机扰动、是否值得研究归一化。答案可以是“证据不足”。

如果 paired CI 跨零、方向不一致、随机扰动有类似效应，或差异主要由重复帧和采样遗漏
解释，当前证据不支持将“速度相关表示归一化”作为主研究方向，建议停止结构改造。
只有现象跨条件稳定且机制证据足够，才值得独立验证；本轮不自动扩大到1000或重新训练。

典型失败模式：错误的数据版本、不同预处理库造成像素哈希不符；不同prompt/融合配置；
小batch浮点近似导致近边界预测改变；短视频重复采样；时间插值遗漏短暂动作/缺少公共区间；
5-shot逐位置原型混合不同动作进度；共享视频/Support导致跨episode相关；历史Test重复查看。

CPU验证记录见 `cpu_validation.json`；这份记录中的真实视频检查只有像素解码，
原生公式核对使用的是小规模合成特征，**均不等于checkpoint正式推理已验证**。
